# pi-studio 生图链路

写 prompt 前先看这一页。风格库的建议必须落到这里列的实际能力上,不要照搬上游那套面向网页版 GPT-Image2 的参数假设。

## 模型

`gpt-image-2` 是 pi-studio 的默认模型,也是唯一支持蒙版的。

| 模型 | engine | 参考图 | 蒙版 | 说明 |
| --- | --- | --- | --- | --- |
| `gpt-image-2` | `openai` | 支持 | 支持 | 默认;文生图 / 改图 / 蒙版 |
| `gemini-3-pro-image-preview` | `gemini` | 支持 | 不支持 | 质量优先 |
| `grok-imagine-image` | `grok` | 不支持 | 不支持 | 标准文生图 |
| `grok-imagine-image-quality` | `grok` | 不支持 | 不支持 | 高质量文生图 |

风格库的 22 个模板都是围绕 gpt-image-2 逆向出来的,换到 gemini / grok 时 guidance 未必成立,别把模板约束当成通用真理。

## 聊天里出图:`image_gen` 工具

只有三个参数:

- `prompt` — 完整画面描述。主体、表情/动作、构图、风格、背景都要写;画面里要出现的文字逐字写出并说明位置。
- `size` — 只有 `1024x1024`、`1024x1536`、`1536x1024`、`auto` 四个值,默认 `1024x1024`。
- `referencePaths` — 参考图路径,相对工作区或绝对路径均可。给了就是照着这些图改,不是从零画;用户在对话里粘贴的图,落盘路径见系统提示。

**没有 quality、background、aspect ratio 参数。** 风格库里写 4:5、3:2、21:9 的模板,`size` 只能取最接近的一档,真实比例靠 prompt 正文描述:

| 模板要的比例 | 用这个 size | prompt 里怎么写 |
| --- | --- | --- |
| 1:1 | `1024x1024` | 正方形构图 |
| 竖版 4:5 / 2:3 / 3:4 / 9:16 | `1024x1536` | 竖版构图,主体居中,上下留白 |
| 横版 3:2 / 4:3 / 16:9 | `1536x1024` | 横版构图 |
| 21:9 这类极端宽幅 | `1536x1024` | 写明「超宽幅画面,左右延展」,并接受实际画布更方 |

透明背景(App 图标、贴纸、母图)在 prompt 正文里写「透明背景 / transparent background」,聊天工具不暴露 `background` 参数。

## 工作流里出图:`imagegen` 步

工作流步骤只有 `prompt` 和 `engine` 两个相关字段,**连 `size` 都没有**,尺寸和比例全靠 prompt 正文交代。gpt-image-2 对应 `engine: 'openai'`。

步骤 prompt 里可以引用前面步骤的产物:

- `{{routine.input}}` — 用户这次运行时填的输入。
- `{{steps.步骤名.output}}` — 指定步骤的文本产物,步骤名要和工作流里一字不差。
- `{{prev.imageUrl}}` — 上一步产出的图片 URL,给 `model3d` 这类吃图的步骤用。

把风格库模板接进工作流时,照仓库里「表情包生成」模板的结构走:`agent`(策划) → `review`(人工确认) → `imagegen`(出图) → `review`(验收)。agent 步负责选型和写 prompt,**不要让 agent 步直接调工具出图**,否则人工确认这一环就被绕过了。现成写法另见 `media.cover`、`media.app-icon-master` 两个节点预设。

## 中文文案

pi-studio 的用户主要出中文图,而 gpt-image-2 的中文字形容易糊。稳妥写法:

- 文案逐字写进 prompt,并标位置(「上方文案:加班到深夜」「下方文案:无」)。
- 限字数,短句优先;标注为「无」的位置要明说不出现文字。
- 明确写上「不增加任何额外文字,不要 Logo、水印、签名、边框或平台标识」。
- 完全不需要文字时,直接写「画面中不要出现任何文字」。

## 别做的事

- 不要建议用户去调 `quality=high` 或别的 OpenAI 原生参数:pi-studio 的两条出图链路都不暴露它们。
- 不要把上游风格库里的案例编号(case 17 这类)当成用户能点开的东西——本目录只带了模板元信息,没有案例正文和图片,编号只用于你自己判断模板方向。
- 不要因为一次生成结果不理想就换模型重试;先改 prompt,换模型要问用户。
