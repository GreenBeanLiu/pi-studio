# 审查清单（按维度）

审查按 SKILL.md 里的顺序逐维过一遍。每个 finding 都要给「组件/文件 → 问题 → 为什么 → 具体改法（用项目写法）」。给不出具体改法的，标为「需要与设计确认」。

## 1. 可访问性（先查，因为最伤）

- 键盘走查：每个流程不碰鼠标能走完吗？（Tab 顺序、Escape 关浮层、Enter/Space 触发、方向键在菜单/标签页/列表内移动）
- 焦点环：只样式化 `:focus-visible` 而不是 `:focus`；不要裸 `outline: none`；用 token 颜色做自定义环（`token.colorPrimary`），保证 ≥2px 可见。
- 命中区：图标按钮 / 关闭按钮是否 ≥ 24×24 CSS 像素（桌面端优先 40×40）？可见元素小可以用伪元素扩展命中区，但命中区不能互相重叠。
- 语义与 ARIA：原生元素优先（`<button>` 做动作、`<a href>` 做导航）；图标按钮必须有 `aria-label`；装饰层 `aria-hidden`；可见文本要出现在可访问名称里。
- 表单：每个输入有 `<label>` 或包裹 label；placeholder 不是 label；错误要 `aria-invalid` + `aria-describedby` 指向错误文案。
- 浮层（Modal/Drawer/Popover）：打开时背景 `inert`、焦点移入、关闭时焦点归还触发点、背景不滚动（`overscroll-behavior: contain`）。
- 动效与缩放：尊重 `prefers-reduced-motion`；Toast 时长要足够读完；不依赖纯颜色传达信息（错误不只靠红色，加图标/文案）。

## 2. 布局与结构

- 分组靠留白不靠线：组间间距 ≥ 组内间距 2 倍；分隔线是最后手段。
- 对齐到共同边缘：别每个块各歪一点；子层级用同一档间距步进。
- 阅读顺序：重要内容靠上、靠前；自上而下、前到后。
- 渐进披露要有可见线索：被隐藏的内容要么露出 16–32px，要么有明确的展开控件；零线索 = 用户以为不存在。
- 控件和内容要能区分：可交互的东西要有背景/边框/固定位置，不能长得和静态文本一样。
- 响应式：断点由内容决定，别照抄设备预设；先测最小和最大尺寸；窄窗口下布局不能塌。桌面端窗口可自由缩放，重点测窄窗口（设置面板、侧边栏是否被挤没）。

## 3. 文案（中文产品，重点）

- 语气分级：成功/引导/空状态可以暖一点；常规操作中性；错误/危险操作冷静、无玩笑；数据丢失要严肃明确。
- 动词开头按钮：`保存草稿` / `删除项目`，不要 `好的！` / `OK`；危险确认按钮要重复后果（`删除该项目？` → `删除项目` + `取消`，而不是 `是`/`否`）。
- 术语一致：菜单叫 `归档`，Toast 就别叫 `移动到存储`；多步流程用一套词（进入=开始，推进=下一步/继续 二选一，完成=完成）。
- 链接描述目的地：`查看导出文档`，不要 `点击这里`。
- 大小写策略统一：全按钮/全标题同一种风格（中文无大小写问题，但中英混排时英文单词风格要一致）。
- **禁止字符串拼接**：`"你有 " + n + " 条消息"` 这种在 i18n / 数量变化时必炸；用完整模板 + 正确复数。中文注意量词（`1 条` / `3 条`）。
- 占位符、空状态、错误提示要具体：`加载失败，请检查网络后重试` 优于 `出错了`。

## 4. 色彩与主题

- 只用 token（见 project-idiom），硬编码 hex 在深浅色切换下必漏。
- 一个颜色一个含义：主色=可交互，主色用在静态文字上会误导点击；填充按钮（背景上色）比「中性底 + 彩色文字」更像主按钮。
- 一个视图最多一个主按钮填色，同级动作保持中性。
- 状态色（success/warning/error）有实际渲染才引入，不造没用的色板。
- 对比度：测「实际渲染的前景 vs 背景」对，不是 vs 页面背景；失败就报出「该对、实测值、差多少」，不要自作主张改色。

## 5. 排版

- 层级：标题按级别递减字号；正文行高 1.5–1.6，标题 1.1 左右；行高用无单位值。
- 少用字重和字号：≤3 种字体；<18px 别低于 400 字重；<300 只用于 ≥28px 的展示字。
- 大标题可微负 letter-spacing，小号全大写标签微正 letter-spacing。
- 数字/表格对齐用 `tabular-nums`（`font-variant-numeric: tabular-nums`）。
- 截断：长文本明确是省略号（`text-overflow: ellipsis`）还是换行；标题不出现孤行/寡妇行。
- 用 CSS 属性而不是原始 tag：`font-weight: 650` 优于 `font-variation-settings`，`font-variant-numeric` 优于 `font-feature-settings`。

## 6. UI 细节与动效

- 同心圆角：外层圆角 = 内层圆角 + 内边距；嵌套元素圆角不一致是最常见的「感觉不对」来源。
- 光学对齐胜过几何对齐：带图标的按钮、播放三角等需要手动偏移。
- 阴影表层次、边框表结构：只为了深度的边框改用分层透明 `box-shadow`；分隔线/选中态/焦点态保留边框。
- 可中断动画：交互态用 CSS transition（可被中断），keyframes 只用于一次性进场序列。
- 进场拆分 + 错开：一次性进场按语义块拆开、错开约 100ms；高频交互不要错开。
- 退场更轻：用固定小 `translateY` 而不是整个高度；进场退场都用 `ease-out`。
- 图标状态切换：用 opacity/scale/blur 交叉淡化（scale 0.25→1，opacity 0→1，blur 4px→0），不要 toggle 显隐；项目无 motion 库，两个图标都留在 DOM（一个绝对定位）+ CSS transition，缓动 `cubic-bezier(0.2, 0, 0, 1)`。
- 图片描边：`1px` 低透明度描边保证深度一致——浅色 `oklch(0 0 0 / 0.1)`，深色 `oklch(1 0 0 / 0.1)`，绝不用 slate/zinc 之类带色中性色。
- `will-change` 只在真实频繁动画的元素上用，用完移除；`transition` 只写具体属性。

## 7. 桌面端特有

- 标题栏 / 侧边导航（NavRail）/ 会话列表（SessionSidebar）的命中区、拖拽、缩放。
- 窗口缩放时布局不塌、滚动条行为正常。
- 深色/浅色外观切换（`appearance`）不能闪白或闪黑，见 project-idiom 规则 6。
- 长内容（对话流、生成历史）的滚动性能与锚点。
